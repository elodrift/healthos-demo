## History

An earlier version of this script hashed the PR head commit's git *tree*.
That was reviewed independently and found to be self-referential and
unsatisfiable: writing `reviews/<tree-hash>.md` is itself a commit, which
changes the head commit's tree, which changes the hash the file needs to be
named after — so no PR that triggered the gate could ever pass. Confirmed by
reproduction (clone, hash, add the named file, recompute — the hash moved).

## What changed, and independent verification of the fix

The script now hashes the PR's diff against `main` via the GitHub compare
API (filename, previous_filename, status, and patch text per changed file,
sorted by filename, joined, sha256'd), with anything under `reviews/`
excluded from the inputs. That decouples the hash from the evidence file's
own existence.

## Known residual limitation (not blocking here)

The GitHub compare API omits `.patch` for very large or binary diffs. A
future PR large enough to hit that would still hash successfully (the `//
""` fallback handles the absent field), but two structurally different huge
diffs that both trip the omission could in theory collide on the non-patch
fields alone. Not a concern at this PR's size; worth keeping in mind if Gate
B is ever exercised against a genuinely large diff.
